# M4: extracting facts from filings (rules first, a local LLM second)

Written when the code was complete (2026-10-04). The accuracy numbers wait
for the labelled set (300 filings, labelled by the human); they go into
`reports/M4_extraction.md`.

## What was built, and why this design

An order win only matters if it is large *for that company*. The size is in
a PDF, in rupees, in whatever words the company secretary chose. M4 turns
that PDF into a number that can be trusted, or into "unknown".

- **Text first.** Attachments are downloaded and their text extracted and
  stored, versioned by extractor, so nothing is re-read without a reason.
- **Rules before a model.** SEBI's disclosure annexure has labelled fields;
  rules read them exactly, for free, in milliseconds. Indian amounts need
  care: "Rs. 1, 303 Crores", "Rupees Twelve Crore Forty Lakh only", ranges,
  and a plausibility floor that rejects "Rs 20" picked from a share price.
- **The LLM only when the rules are unsure.** A local model (Ollama) answers
  under a JSON schema; its answer is then *validated*: the amount must
  appear in the text and be plausible. A failed validation keeps the rules'
  answer. Replies are cached and re-validated when the checks change.
- **Everything is versioned by content.** The extractor version includes a
  hash of the extraction code: change a regex and results are recomputed
  into new rows rather than left stale under a current name.
- **An honest evaluation set.** The sample was drawn from months the rules
  were never tuned on, stratified, and committed before labelling. Half the
  proposals shown to the labeller come from the rules and half from the
  LLM, at random, so anchoring on a proposal can be measured.
- **Company size, point in time.** Quarterly revenue comes from NSE's
  results filings (XBRL). `AsOf.trailing_revenue` uses only quarters that
  were public at the moment asked, and gives no answer rather than a stale
  or patched-together one.

## Key concepts

- **The LLM extracts, code decides.** The model never chooses a trade; it
  fills a form, and deterministic checks accept or reject the form.
- **Validation against the source.** "The number must be in the text" turns
  a fluent guess into a verifiable claim.
- **Held-out data.** Accuracy measured on the examples you tuned on is a
  memory test. The labelled set comes from different months.
- **Confidence intervals for proportions.** "93% correct on 280" is a range,
  not a point; the report uses Wilson intervals.

## What could go wrong

- Scanned PDFs have no text; they are counted as "needs OCR", not guessed.
- A model update changes answers silently: the model name is part of the
  version, and a new model is a new extractor and a new paper-run design.
- The labeller can be wrong or anchored; the guide and the random proposer
  exist to measure that, not to remove it.

## Read next

- Edwin B. Wilson, "Probable Inference, the Law of Succession, and
  Statistical Inference", *Journal of the American Statistical Association*
  22(158), 1927: the interval used for accuracy.
- Amos Tversky and Daniel Kahneman, "Judgment under Uncertainty: Heuristics
  and Biases", *Science* 185, 1974: anchoring, the bias the labelling
  protocol measures.
- Ollama's API documentation, the section on structured outputs (the
  `format` field with a JSON schema).
