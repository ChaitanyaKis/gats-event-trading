# M2: reference data and entity resolution

## What was built, and why this design

Before any return can be measured, three questions need exact answers: *which
security is this filing about*, *what were its prices on day D*, and *was the
market open*. M2 answers them point-in-time:

- **Security master.** NSE identifies a listing by symbol (which changes:
  ZOMATO → ETERNAL), BSE by scrip code (permanent), both carry ISINs. Listings
  that share an ISIN are joined with **union-find** into one `security_id`,
  each identifier with a validity window. IDs stay stable across rebuilds.
- **Versioned reference files.** BSE's scrip list and NSE's ASM/GSM lists
  publish only "today". Each day's file is applied as a snapshot to
  **type-2 slowly changing dimension** rows (`valid_from`/`valid_to`): a new
  row only when something changes, instead of a full copy every day.
- **Cross-exchange events.** The same disclosure is usually filed on both
  exchanges minutes apart; pairing them (attachment size, time gap, topic
  words; 47-50/50 correct on a hand check) prevents double counting.
- **Calendar and corporate actions,** both derived from evidence: the daily
  files themselves reveal sessions (even Sunday budget sessions), and NSE's
  corporate-action feed supplies the split/bonus multipliers that its own
  `PREV_CLOSE` does not apply.

## Key concepts

- **Identifiers are time-dependent.** "ETERNAL" did not exist in 2024; NSE's
  APIs still report it for 2024 filings because they answer with *today's*
  symbol. Every join across time translates identifiers to the right date.
- **Split-safe returns:** on an ex-date, one old share became *m* new ones, so
  the return is `close × m / prev_close − 1`. Without *m*, a 1:1 bonus looks
  like a −50% crash. Value transfers no multiplier captures (rights,
  demergers) are flagged and excluded rather than guessed.
- **Precision vs recall** in matching: a missed pair double-counts an event;
  a wrong pair merges two. Measure both, by hand, before trusting a rule.

## What could go wrong

- Reference data you only started recording today has no history; mapping it
  backwards is an assumption. It is documented, and `available_at` keeps the
  honest first-seen time for anyone who must not use it.
- A symbol reused by a different company with no recorded rename would be
  treated as one listing; reuse after a recorded rename is handled.
- Exchanges change free-text formats (corporate-action subjects); the
  classifier flags what it cannot read instead of guessing.
