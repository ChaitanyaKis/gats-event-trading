# M5: intraday data and reaction curves

Written when the code was complete (2026-10-04). The bars need the Upstox
token and the study needs the recorder's measured latency; the result goes
into `reports/M5_reaction_curves.md` and gate G1b.

## What was built, and why this design

M3 measures a filing's effect with daily prices. A strategy that acts
within minutes needs to know how the reaction unfolds *inside* the day, and
how much of it is left by the time an order could reach the market.

- **One-minute bars as files, not rows.** Bars are stored as Parquet, one
  file per instrument and month, and queried with DuckDB. A database table
  with hundreds of millions of rows would be slow and fragile; columnar
  files are compact, immutable and easy to back up. A small table records
  which months are complete, so fetching resumes where it stopped.
- **Keys that survive renames.** Upstox identifies a stock by its ISIN, the
  same identifier the security master is built on, so ZOMATO becoming
  ETERNAL does not break the join.
- **Only what is needed.** Bars are fetched for the sessions around each
  in-scope event (the one before, the event's, the one after), for the
  stock and the benchmark index, not for the whole market.
- **A pre-registered reaction study.** For each event the price path is
  measured from the first moment a trade was possible: the filing's
  availability plus the *measured* delay of this system, not an assumed one.
  The study refuses to run until that delay has been measured by the live
  recorder.

## Key concepts

- **Latency is part of the strategy.** If most of a move happens in the
  first minute and the system needs two, the edge in the backtest belongs
  to someone faster. Measuring the delay (median and 95th percentile)
  before testing is what keeps the test honest.
- **Decision time versus data time.** A bar is known only once it has
  closed. An order decided on a bar can at best fill in the next one.
- **Columnar storage.** Reading one column of a billion rows touches only
  that column. That is why analytics formats differ from transactional ones.
- **G1b.** The same pass criteria as G1, after real latency and intraday
  costs: a daily effect that vanishes at realistic speed is not tradable.

## What could go wrong

- The candle API is documented but unprobed until the token exists; the
  first real reply is checked against NSE's own end-of-day file.
- Minute bars begin in January 2022: earlier events cannot be studied
  intraday, which shortens the sample.
- A stock that does not trade for minutes has no bars for those minutes;
  the study must not read a missing bar as "no move".

## Read next

- The Apache Parquet documentation (parquet.apache.org): the file format.
- The DuckDB documentation on reading Parquet files (duckdb.org/docs).
