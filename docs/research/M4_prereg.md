# M4 pre-registration: does the size of an order, relative to the company, matter?

- **Study:** `m4-order-magnitude` · **Registered:** 2026-10-03, before any
  return was computed for order-win filings, with or without their size
  (M3 has not been run; no revenue backfill exists yet).
- **Config:** `configs/studies/m4_magnitude.yaml`, SHA-256 (LF line endings)
  `4f2da67ac8cc6718c5b29bb65e20bde41acdd7466f748c3f1017f607cb566ec8`.
  The engine refuses to run if the file's hash differs. Any change is a new
  study and a new trial.
- **Taxonomy:** `taxonomy-v1+6f16e1c9`.

## 1. Question

DESIGN's thesis is that an order worth 40% of a company's revenue matters
and one worth 0.4% does not. Do order wins that are **large relative to the
company** earn a positive abnormal return net of costs, in the held-out
test period? This is T4.7's re-test of ORDER_WIN with a magnitude filter.
"Size does not help" is an acceptable, reportable answer.

## 2. Data

- M3's data: NSE filings, NSE daily prices, Nifty 500, the same
  availability rule.
- **Order value**: `amount_inr` from the extraction cascade (rules, then
  the local LLM), the newest extraction per filing. Foreign-currency
  orders have no rupee value and are not in the sample.
- **Company size**: trailing revenue, the sum of the four latest
  consecutive quarters of `RevenueFromOperations` (consolidated preferred)
  from results whose dissemination was before the filing became available
  (`AsOf.trailing_revenue`). Events with no such figure are dropped.
- The run requires M3's data readiness and, in addition, that the T4.6
  evaluation has been run on at least 300 labels: the report quotes the
  cascade's measured amount accuracy next to the result.

## 3. Hypothesis and trades

- **Confirmatory:** ORDER_WIN filings with order value ÷ trailing revenue
  **≥ 10%**, long, M3's trades unchanged: enter at the first regular
  session open strictly after availability; exit at the close of the entry
  session and 1, 3 and 5 sessions later; market-adjusted against the Nifty
  500; M3's flat 0.5% round-trip cost, kept so the two studies compare.
- H1 for each exit: mean net abnormal return > 0 (one-sided).
- **Reported only:** thresholds 1%, 5% and 20%, and the events dropped for
  each reason (no amount, no revenue, below the threshold).

## 4. Filters

M3's, applied before returns are looked at: series EQ, 20-session median
traded value ≥ Rs 1 crore, previous close ≥ Rs 10, no locked entry day, no
entry gap of 19.5% or more, no rights/demerger days in the window, and the
5-session cooldown per security.

## 5. Split, holdout and multiple testing

- **Train:** entries 2022-01-01 → 2023-12-31. **Test:** 2024-01-01 →
  2026-09-30, decided on the test period only, computed once.
- **This is the second study to read this test period** (M3 reads it
  first). To pay for that, the false-discovery level is halved:
  Benjamini–Hochberg at **q = 0.025** over this study's 4 tests, with
  FCR-adjusted bounds at that level. The experiment registry counts it as
  a new trial.
- Statistics otherwise as M3: date-clustered standard errors, a
  date-clustered bootstrap (10,000 resamples, seed 20261003).

## 6. Pass criteria

An exit passes only if, in the test period: N ≥ 100 after filters; mean net
abnormal return > 0; selected by BH at q = 0.025; FCR-adjusted lower bound
> 0. Whatever the outcome, the decision goes to the human with the report.

## 7. Known limits, stated in advance

- Extraction errors blur the size filter. The T4.6 accuracy is reported
  with the result; a wrong amount can put an event on the wrong side of
  the threshold in either direction.
- Revenue is as reported in XBRL; banks and NBFCs report differently and
  have no figure, so they are dropped.
- The LLM extracts facts from each filing's own text only. It is not asked
  to judge the event, so its training data cannot leak outcomes into the
  feature.

## 8. Reporting

`reports/M4_magnitude.md`, regenerated by one command: the decision table,
train and test for every exit, the exploratory thresholds, every filter's
count, and the extraction accuracy quoted from `reports/M4_extraction.md`.
